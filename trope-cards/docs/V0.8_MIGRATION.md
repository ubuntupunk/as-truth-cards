# v0.8 Migration

Apply after v0.7.

## Database changes

1. Create `argument_chain_kind`.
2. Create `inference_step_role`.
3. Create `inference_step_relation_type`.
4. Create `argument_chains`.
5. Add nullable `argument_chain_id` to `inference_steps`.
6. Create `argument_chain_steps`.
7. Create `inference_step_relations`.

The `argument_chain_id` column is intentionally nullable so existing v0.7 inference steps remain valid during incremental migration.

## Seed policy

Existing v0.7 inference steps are not rewritten. v0.8 adds named chains and counter/alternative steps around them.

A seed runner must resolve symbolic card and inference labels to actual UUIDs. Missing references should be reported and skipped; never create orphan relationships.
