# v0.10 Migration

Adds:
- `trope_graph.card_axis` enum
- `trope_graph.card_axes` table

Migration is additive. Existing cards, claims, relationships, and reasoning records remain
valid, and no column on an existing table is altered or dropped.

## What changed

Every card was already authored with an `axis` list, but the field was typed `string[]` and
read by nothing. It was dead data: a corpus with no axis at all would have validated
cleanly. Migration 0008 makes it a first-class, ordered relationship.

- **`card_axes`** holds one row per (card, axis) pair, with an `ordinal` so the primary axis
  is explicit. `ON DELETE CASCADE` from `cards`.
- **`card_axis` enum** adds `HISTORICAL` to the existing three values.
- **Two unique indexes**, `(card_id, axis)` and `(card_id, ordinal)`. Both are required:
  the first prevents a duplicated classification, the second prevents two axes competing for
  the primary position.

The seeder now writes `card_axes` and reconciles it idempotently, preserving row ids across
re-seeds. The verifier diffs each card's persisted axes against the authored list, in order,
rather than only counting rows.

## Validation requirements

1. A card must carry at least one axis. An unclassified card is the exact condition this
   migration exists to close.
2. Axis values must come from the `card_axis` enum. Free text is rejected at the type level,
   by the seeder, and by `validate-draft.mjs`.
3. A card must not repeat an axis.
4. Axis order is significant: ordinal 0 is the designated primary axis, and ordinals are
   contiguous from 0.
5. Axis is independent of `primaryType`, of collection (suit), and of epistemic status.
   `CONTESTED` is **not** an axis value; it is an epistemic status and lives in
   `epistemic_status`. Deriving one from the other would make them have to agree forever.
6. `cards.primaryType` is retained as legacy content-shape metadata. It is not the source of
   axis and must not be used to derive or default it.

## Current corpus

47 cards, 56 axis values, 9 multi-axis cards. By value: `FACT_REBUTTAL` 27, `TACTIC` 18,
`THEOLOGICAL` 10, `HISTORICAL` 1.

`HISTORICAL` exists for one card, `canaanite-card`, authored as a continuity argument. Folding
it into `FACT_REBUTTAL` to fit the original three axes would have discarded a real editorial
classification, so the value was kept and the enum grew instead.

## Notes for the next migration

- No graph API or frontend consumer reads `card_axes` yet. The contract is currently enforced
  by the seeder, the verifier, and the static test suite; there is no compose service to
  update.
- `CONTESTED` remains available as a collection but has no cards. It is not an axis, and
  should not be migrated into `card_axes` if that is ever reconsidered — the dimension is
  already modelled by `epistemic_status`.
